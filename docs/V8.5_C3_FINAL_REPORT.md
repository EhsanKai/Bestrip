## 1. Duffel test-mode cancellation

Multi-step, operator-driven (`services/ticket_operations.py`, `models/ticket_ops.py`):

`check_cancellation_eligibility` → `approve_cancellation` → `execute_cancellation`.

* **A inspect / B quote / C show consequences** — `check_cancellation_eligibility`
  creates a `POST /air/order_cancellations` (which does **not** cancel) and stores
  the provider-stated `refund_amount`, `refund_currency`, `refund_to`, conditions.
* **D explicit Ops confirmation** — `approve_cancellation` records the operator +
  reason; `execute_*` refuses unless state is `APPROVED`.
* **E execute** — `POST /air/order_cancellations/{id}/actions/confirm`.
* **F persist truthful state** — derived from the provider response, never assumed.

### Cancellation state machine

`PENDING_ELIGIBILITY → ELIGIBLE/INELIGIBLE → APPROVED →` one of:

| terminal state | meaning |
|---|---|
| `CANCELLED` | order cancelled, refund side tracked separately |
| `REFUND_PENDING` | cancelled, refund owed but **not settled** — *not* a refund |
| `REFUNDED` | cancelled, full stated refund settled |
| `PARTIALLY_REFUNDED` | cancelled, a fee was retained |
| `NON_REFUNDABLE` | cancelled, provider stated nothing is due |
| `CANCELLATION_FAILED` | provider did not complete it; order may be live → booking recovery flag set |

**`CANCELLED != REFUNDED`** is enforced in the model: `CancellationResult` carries
`state` *and* an independent `RefundStatus` (`UNKNOWN/NONE/PENDING/PARTIAL/FULL`);
`REFUNDED` is rejected without a settled amount, `NON_REFUNDABLE` is rejected with a
positive refund. If Duffel confirms the cancellation but states no `refund_amount`,
the persisted state is `REFUND_PENDING` + `RefundStatus.UNKNOWN` — never `REFUNDED`,
never a number inferred from the original fare.

## 2. Change / date / flight operations

Capability-first (`check_change_capability`): `GET /air/orders/{id}`, read
`available_actions` / `changeable`. If the order cannot be changed →
**`NOT_SUPPORTED`** shown plainly, no emulated UI. Where supported, the console
states that a priced change offer requires the replacement itinerary built against
the order; an approved change with no attached change-offer id is recorded as
**blocked** (`ChangeState.FAILED` with a truthful detail), never faked. Duffel's real
model is a replacement — `ChangeKind` distinguishes `ORDER_CHANGE` from
`REBOOK_REPLACEMENT` and the copy never calls a replacement a "ticket change".
Provider methods added: `create_order_change_request`, `get_order_change_offer`,
`create_and_confirm_order_change`.

## 3. Recovery Center — safe actions

`INSPECT → REVALIDATE → FIND REPLACEMENT → COMPARE → APPROVE → EXECUTE`
(`start_recovery` / `record_recovery_candidate` / `approve_recovery` /
`execute_recovery` / `abandon_recovery`). The candidate carries old-vs-new route,
dates, carrier, flight number, supplier fare, baggage, connection note, transit
minutes; the console shows a side-by-side ORIGINAL vs REPLACEMENT panel.
**`execute_recovery` never auto-books** — it records the approved decision and
states that the replacement leg must be booked through the normal acquisition +
order flow. Every step records reason, booking id, candidate, operator, timestamp,
provider result and an audit event.

## 4. Ops ticket actions

`VIEW_PROVIDER_DETAILS`, `CHECK_CANCELLATION_ELIGIBILITY`, `CANCEL`,
`CHECK_CHANGE_CAPABILITY`, `FIND_REPLACEMENT`, `START_RECOVERY` — availability is
real. An action unavailable for the provider/order stays **visibly disabled with a
truthful reason** ("This booking created no provider order (demo / not issued)…").
The old "not implemented" placeholder buttons are gone. No fake-success controls.

## 6. Airline performance analytics

`GET /api/v1/ops/airlines?dimension=marketing|operating` (`persistence/airlines.py`)
— tickets total/issued/failed, issuance-failure rate, bookings, supplier spend,
average fare, Detoura gross revenue (apportioned per booking to the issuing
carriers), **Detoura margin only where the economics row is cost-complete**,
cancellation / change / recovery counts and rates. Marketing and operating are
separate dimensions with a UI toggle — never silently merged. Unknown costs →
`UNKNOWN`, never zero.

## 7. Idempotency / destructive-action safety

`ticket_operations` rows carry a server-issued `operation_id` and an optional
client idempotency key (unique index). `execute_cancellation` / `execute_recovery`:
an execute against a terminal operation returns the stored result and makes **no
provider call**; a replayed idempotency key returns the prior operation. `approve`
is required before `execute`. The client body accepts only `reason` +
`idempotency_key` — never a refund amount, change fee or net delta (test:
`test_client_cannot_forge_refund_amount`).

## 8. Audit

Every step writes an audit event: `CANCELLATION_ELIGIBILITY_CHECKED`,
`CANCELLATION_APPROVED`, `CANCELLATION_EXECUTION_ATTEMPTED`,
`CANCELLATION_EXECUTED` / `_FAILED`, `CHANGE_CAPABILITY_CHECKED`,
`CHANGE_APPROVED`, `CHANGE_EXECUTION_*`, `RECOVERY_STARTED`,
`RECOVERY_REPLACEMENT_FOUND`, `RECOVERY_APPROVED`, `RECOVERY_EXECUTED`. Payloads
carry ids, states and the operator reason only — **no passport/document data or
other PII** (audit `target_type="ticket_operation"`; the ops booking-detail audit
view now also surfaces operation-scoped events).

## 9. DEMO_ONLY behavior

A DEMO booking has no `ord_...` id. Every provider action returns
**`NOT_SUPPORTED_IN_DEMO`** (recorded, never persisted as provider-confirmed) and
the console buttons are disabled with the truthful reason. No pretense that a
Duffel cancellation, refund or mutation occurred.

## 10. Test-mode safety

`duffel_for_ops()` refuses a non-`duffel_test_` token (returns `None` → action
reported unavailable). Every provider method: token-prefix guard, `max_calls`
ceiling, id-shape validation (`ord_`/`ore_`/`ocr_`/`oco_`/`och_`) before a URL is
built, and `assert_test_mode` / `live_mode is False` on the response. No
production/live mutation is reachable from this milestone.

### Agent 5 — adversarial QA

**APPROVED.** First pass **REJECTED** with 3 blocking findings, all fixed and
re-verified:

1. `execute_cancellation` — the `DuffelOrderNotFound` (confirm-404) branch built a
   `CANCELLATION_FAILED` result but did not `return`, falling through to an
   unbound `raw` → `UnboundLocalError` → HTTP 500, operation stranded in
   `APPROVED`. Now persists the failed result, sets the recovery flag, audits,
   returns.
2. Partial refunds were labelled `REFUNDED` / `FULL` — `order_paid_amount` was
   never populated so `PARTIALLY_REFUNDED` was unreachable on the Duffel path.
   `check_cancellation_eligibility` now computes what was paid (per-person fare ×
   party over the affected legs) into the quote; a provider `penalty_amount > 0`
   also marks the result partial. Refund amount is still provider-sourced only.
3. Idempotency TOCTOU — overlapping executes both passed the pre-checks and both
   called the provider; the loser's "already confirmed" error clobbered the good
   result. New atomic `ops_store.claim` (conditional `UPDATE` through the single
   serialised `db.write` lock) moves `APPROVED → EXECUTING`; the loser returns
   the in-flight op. New non-terminal `CancellationState.EXECUTING`.

Agent 5 non-blocking notes actioned: stale-`EXECUTING` reclaim after
`_EXECUTING_STALE_SECONDS` (`a5a04be`); `check_change_capability` no-token →
`ChangeState.CAPABILITY_UNKNOWN` not `NOT_SUPPORTED`; airline op-rate no longer
counts a whole-order op once per leg.

Agent 6 non-blocking hardening — actioned at `4a94858`:

* `_persist_cancellation_result` terminal write is now conditional
  (`WHERE state NOT IN` the terminal set) so a late stale-`EXECUTING` reclaim
  cannot overwrite a good `REFUNDED` row; the idempotency-key tag write is
  wrapped so a key collision never turns a persisted cancellation into a 500.
* `execute_change` got the same atomic `APPROVED → EXECUTING` claim and
  idempotency-key short-circuit before `create_and_confirm_order_change` (that
  path is currently unreachable — nothing writes `change_offer_id` yet — the
  guard is in place for when change offers are wired).

Agent 6 non-blocking notes **not** actioned (documented milestone limitations):
a mistyped client idempotency key matching another operation returns that
operation's data (all callers are `require_ops`-authenticated); the unused
`duffel.redact()` helper is dead code; `_guard_mutation` is called on the `get_order`
read path (behaviour correct — fail-closed, counts against `max_calls` — name
overstates it); `order_paid` uses `quoted_price` as a last-resort fallback and
can therefore be pessimistic (errs toward "partial", never over-claims a full
refund); a `CANCELLATION_FAILED` op is not retryable in place but a fresh
eligibility check mints a new operation.

## 15. Known non-blocking limitations (carried into V8.5 release)

* The consumer booking flow's traveller step requires a title/gender select per
  traveller before "Continue to review" enables — pre-existing, not C3.
* `route_is_international` recognises ~20 EU airports and needs both endpoints
  mapped; a leg to an unmapped airport is treated as domestic. Mitigated:
  Duffel test mode issues without passport data, so `documents_required` never
  blocks a sandbox booking on this.
* `execute_change`'s provider path is not reachable from the console (no
  `change_offer_id` is ever written) — capability inspection and the
  NOT_SUPPORTED / blocked outcomes are, and the concurrency guard is in place.
* Agent 6 non-blocking notes in §13 that were left as documented limitations.
* A hard process kill inside the ~sub-second window between the provider confirm
  returning and the result write leaves a cancellation op in `EXECUTING`;
  reclaimed after 120 s, or a fresh eligibility check mints a new operation.
