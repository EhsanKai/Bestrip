## Architecture Findings

- Framework / build system: Vite 8 + React 19 single-page application.
- Rendering model: client-rendered SPA. `index.html` contains crawlable head metadata, but homepage body content is rendered after JavaScript executes.
- Routing model: consumer screens are in-memory state inside `/`; `/ops` mounts the operations app. Static hosting rewrites all paths to `index.html`.
- Public indexable routes: `/` only.
- Private/transient routes and surfaces: `/ops`, login/account, My Trips, checkout, payment, booking progress, documents, search/results/detail/compare screens. Most consumer private/transient surfaces are not distinct URLs today, but runtime metadata marks non-home app screens as `noindex,nofollow`.
- Deployment assumption: production builds should set `VITE_PUBLIC_SITE_URL` to the exact public consumer origin. Without it, generated local artifacts avoid hard-coded guessed domains and emit relative homepage metadata plus an empty sitemap with a deployment note.

## SEO Defects Found / Fixed

- Medium: homepage metadata was minimal and lacked canonical, robots, OG, Twitter card, and structured data foundation.
- Medium: `robots.txt` and `sitemap.xml` hard-coded `https://detoura.app`, creating stale-domain risk if the brand/domain changes.
- Medium: arbitrary static-hosting paths rendered the SPA shell as an apparently valid page, creating a soft-404/indexation risk.
- Medium: app/private screens had no runtime indexation policy.

## Remaining SEO Limitations

- Homepage body content is not present in initial HTML because the app is client-rendered.
- Static-hosting rewrites still return HTTP 200 for unknown paths; the frontend renders Not Found/noindex after JS, but true HTTP status requires hosting/server support.
- Production sitemap/canonical correctness depends on setting `VITE_PUBLIC_SITE_URL` in the deployment environment.
- Future destination/inspiration SEO requires approved first-party content and route architecture; it was intentionally not created here.

## Deployment Requirements

- Set `VITE_PUBLIC_SITE_URL` to the exact public consumer origin during production build.
- Keep private routes/authenticated resources protected by backend authorization. robots.txt remains crawl guidance only.
- If deploying staging environments that should not be indexed, add a deployment-level noindex/robots policy or build-time environment rule in a dedicated deployment slice.

## Future Backend / Infrastructure Work

- Add real HTTP 404 handling for unknown public paths if the hosting layer can distinguish approved SPA routes.
- Consider SSR/prerendering for `/` and future approved public content routes before launching a content-driven SEO program.
- Add deployment checks that fail production builds if `VITE_PUBLIC_SITE_URL` is absent.
